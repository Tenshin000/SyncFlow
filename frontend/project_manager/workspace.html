📖 Schedule Metrics, Floats & Network Diagram Legend PMBOK Guide
Expand Guide ▾
⏱️ 1. Forward & Backward Dates
  • Early Start (ES): Earliest point an activity can start based on predecessor Early Finishes.
  • Early Finish (EF): EF = ES + Duration. Earliest completion date.
  • Late Finish (LF): Latest point an activity can finish without delaying project completion.
  • Late Start (LS): LS = LF - Duration. Latest point an activity can start.
📐 2. The Three Types of Float
  • Total Float (TF): TF = LF - EF = LS - ES. Permissible activity delay without postponing the final project completion.
  • Free Float (FF): FF = min(ES_succ - lag) - EF. Permissible activity delay without delaying the Early Start of any successor.
  • Project Float: Project Float = Imposed Deadline – Planned Finish. Surplus or deficit buffer between client commitment and calculated finish. Owned by the PM.
🔥 3. Critical vs Near-Critical Paths
  • Critical Path (TF = 0): The longest sequence of dependent activities. Directly dictates the project minimum duration. Any delay here delays the entire project!
  • Near-Critical Path (0 < TF ≤ Threshold): Paths with very small float. Highly vulnerable: a minor delay turns them critical, shifting project delivery risk.
  • Flexible Tasks (TF > Threshold): Activities with comfortable schedule contingency.
🔀 4. AON (CPM) vs AOA (PERT) & Dummy Links
  • Activity-on-Node (AON): Nodes = Activities (with CPM blocks). Arrows = Precedence dependencies.
  • Activity-on-Arrow (AOA): Nodes = Milestone Events (with TE, TL, Slack). Arrows = Activities (with te, σ²).
  • Dummy Activity (d = 0): Dashed arrows carrying 0 time/cost, required in AOA to enforce logical precedence and avoid ambiguous parallel arrows between the same two events.

6. Control Schedule — Operational Monitoring, Task Execution & S-Curve

Monitor task execution states (Not Started, In-Progress, Completed, Verified by Controller), evaluate leading and lagging performance metrics against the approved baseline, and assess cumulative project progress using the Earned Value S-Curve.

📖 Control Schedule KPIs, Earned Value & Status Color Legend PMBOK Guide
Expand Guide ▾
🎨 1. Task Execution Status Colors
  • ⚪ White — Not Yet Started: Work has not commenced (0% completion). Activity is queued in the baseline schedule.
  • 🟡 Yellow — WIP (Work-in-Progress): Work has begun and is actively ongoing (1% to 99% completion). Actual start date recorded.
  • 🟢 Green — Completed: Execution is 100% finished by the delivery team. Actual finish date recorded.
  • 🔵 Blue — Completed & Verified: Deliverable has been both finished (100%) and formally validated/signed off by the Controller.
📐 2. Earned Value KPIs (Schedule)
  • Planned Value (PV): Budgeted work scheduled up to the status date: PV = Planned Progress × Duration.
  • Earned Value (EV): Budgeted work actually accomplished: EV = Actual Progress % × Duration.
  • Schedule Variance (SV): SV = EV - PV. If SV > 0, ahead of schedule; if SV < 0, project is experiencing slippage.
  • Schedule Performance Index (SPI): SPI = EV / PV. Efficiency ratio. Target ≥ 1.00. SPI < 1.0 indicates slower execution than planned.
🔮 3. Leading vs Lagging & EAC Forecast
  • Leading Indicators (Predictive): Early warnings such as Forecast Finish (EACt = Planned / SPI), Critical Path slippage projection, and Project Float buffer remaining.
  • Lagging Indicators (Historical): Measured results of past work: tasks completed, actual duration variance, and Controller verified deliverables.
  • Critical Path Slippage: Unrecovered delay on critical path activities directly extends total project finish date.
📈 4. S-Curve & Banana Envelope
  • Early Curve (PV Early): Cumulative progress if all activities start at their Early Start (ES). Represents aggressive schedule.
  • Late Curve (PV Late): Cumulative progress if all activities start at their Late Start (LS). Represents relaxed boundary.
  • Banana Envelope: The allowable execution area between Early and Late curves. EV within envelope = acceptable float usage. Below Late curve = severe slippage requiring recovery actions (fast-tracking/crashing).

📈 Project S-Curve (Cumulative Progress Envelope vs Timeline)

Compares cumulative planned progress over time through the Early Curve ($PV_{\text{Early}}$) and Late Curve ($PV_{\text{Late}}$), forming the allowable execution envelope (Banana Curve), alongside the Actual Earned Progress ($EV$) curve and projected forecast.

━ Early Curve (PV Early) ━ Late Curve (PV Late) ● Actual Earned (EV) ╌ Forecast Trajectory | Status Date
PMBOK S-Curve Interpretation Guide: The shaded area between the Early and Late curves forms the Schedule Envelope ("Banana Curve"). If the Actual Curve (EV) remains inside this envelope, project execution is operating within allowable float reserves. If the curve drops below the Late curve, schedule slippage is exceeding allowable tolerances and requires immediate corrective actions (e.g., fast-tracking or crashing). If it runs above the Early curve, the project is ahead of its aggressive schedule plan.
